# FastSignalTraceLACpp 2.1.0

C/C++ 保守信号追踪器，默认 cpp 模式，共享 SourceInsightCli 的函数、调用点和回调绑定模型。

LA 指 Linux/Android 源码分析；随 Skill 安装的单文件 EXE 在 Windows x64 上运行，无需另装 .NET。顶层 fastsignaltrace 会自动将普通 C/C++ 路由到本工具，也可显式指定 -Language Lacpp；UEFI 工程保留独立路由。

2.1.0 默认向 stdout/echo 完整输出信号消费链，例如 source -> middle -> sink；提供方程输出文件时也会回显。`--chains-output <file>` 同时保存完全相同的链文本。`--equations-only` 显式恢复旧的方程机器接口，不展开消费链。

循环先输出 `Loop#N = Loop(全部成员)` 和该循环的全部内部边，再输出根到终端的 SCC 路径；没有深度/路径数限制，成员和关系不会静默省略。多输入方程的图是依赖并集，不等同运行时求值顺序。大型工程可能产生数千万路径，可用系统重定向或 scripts/run-compressed.py 无损保存 stdout；工具不因此减少结果。

自包含 DLL 包：`releases/cpp/fastsignaltrace-lacpp-2.1.0-win-x64-self-contained.zip`。完整解压后有主 DLL、EXE 启动器、runtimeconfig/deps 与本地 .NET 运行时，无需目标机安装 .NET。共享 Core 代码内嵌主 DLL。普通托管 DLL 自身不是 .NET 运行时，请复制完整包；已安装兼容运行时也可 `dotnet fastsignaltrace-lacpp.dll <root>`。公开托管入口为 `FastSignalTraceLACpp.Tool.Run(string[] arguments)`。

```powershell
fastsignaltrace-lacpp.exe <source-root> --output equations.txt --variables-output variables.tsv --verbose
```

可选 --evidence-output、--manifest-output、--index-output、重复 --exclude、--parser tolerant、--strict。
默认有输出文件时同时写出 <output>.evidence.jsonl 与 <output>.manifest.json。manifest 披露源码 hash、诊断及精度范围。--index-output 生成与 SourceInsightCli 相同的 calling 索引。

标准方程 <domain>:<input+input>=<output>；输入/read=Producer，输出/write=Consumer。变量表保持六列。回调地址写入 CallbackSlot，调用读取对应槽；绑定不是执行调用。普通赋值、初始化、返回值、参数映射和结构化条件依赖有源码证据；多目标使用保守并集。

本版本不展开 include/宏，不执行构建脚本；仅 tolerant 前端。没有配置化预处理、完整 C++ 类型/模板/虚派发或精确内存别名副作用分析。--config/--define/--compile-commands/clang 尚不支持并明确拒绝。未知框架返回值标 ExternalReturn，不把静态依赖当作运行时可达证明。

退出码 0 输出成功，2 参数错误，3 无支持输入，4 运行失败，5 strict 下遇到诊断/不确定性。旧 UEFI 内核回归用 --mode legacy-uefi；UEFI 正式分析使用独立 UEFI 工具。

Windows x64 release 目录含单文件 EXE 与本手册。源码构建要求 .NET 8+，联合 C/C++ fixture 与 Harness 验证使用 ../SourceInsightCli/tests/run-fixture.ps1。源码和 Harness 不改写。
