# fastsignaltrace-csharp 使用手册

`fastsignaltrace-csharp.exe` 是 FastTool 系列中的 C# 静态信号追踪 CLI。它把指定文件夹视为源代码根目录，扫描其中的 C# 类型级字段，识别信号的生产/消费角色，并为 `if/else/switch` 控制结构生成标准方程。

## 1. 最快用法

```powershell
fastsignaltrace-csharp.exe "D:\Work\MyProject"
```

标准方程默认逐行写到标准输出，日志不会混入其中，便于自动化工具直接捕获：

```text
Runtime_Fork_A_Test_cs_1145:GlobalClass.Signal_B+Test.Signal_A=Test.Signal_C
```

含义：相对扫描根目录的 `Runtime\Fork A\Test.cs` 第 1145 行开始的控制结构中，`GlobalClass.Signal_B` 和 `Test.Signal_A` 共同决定 `Test.Signal_C`。

## 2. 命令行

```text
fastsignaltrace-csharp.exe <源代码根目录> [选项]

-o, --output <文件>              把标准方程写入 UTF-8 文件；默认写到标准输出
    --variables-output <文件>    额外写出全局变量角色 TSV 清单
    --exclude <目录名>           额外排除一个目录名；可重复使用
-v, --verbose                    把扫描统计和警告写到标准错误
-h, --help                       显示帮助
    --version                    显示版本
```

同时保存方程和变量角色：

```powershell
fastsignaltrace-csharp.exe "D:\Work\MyProject" `
  --output ".\equations.txt" `
  --variables-output ".\variables.tsv" `
  --verbose
```

自动化调用时可直接读取标准输出：

```powershell
$equations = & .\fastsignaltrace-csharp.exe "D:\Work\MyProject"
if ($LASTEXITCODE -ne 0) { throw "scan failed" }
```

## 3. 标准方程规则

方程格式固定为：

```text
<方程组名字>:<输入信号1>+<输入信号2>=<输出信号>
```

- 方程组名字是“相对源码路径（路径分隔符、空格和点替换为下划线）+ 控制结构起始行”。例如 `Runtime\Fork A\Test.cs` 第 1145 行得到 `Runtime_Fork_A_Test_cs_1145`。这可以区分不同 fork/子项目中复用的同名源码。
- `if/else if/else` 链以最前面的 `if` 行为该组起点；嵌套的独立 `if` 也会建立自己的方程组。
- `switch` 以 `switch` 关键字所在行为起点。
- 输入包括赋值右侧读取的全局字段，以及决定该写入能否发生的 `if` 条件、`switch` 选择表达式和嵌套控制条件中的全局字段。
- 同一控制域多次写入同一输出字段时，所有可能输入取并集，并只输出一条稳定排序的方程。
- 仅由常量决定、且控制条件也不读取任何全局字段的写入会记录变量角色，但不会伪造无输入的标准方程。

## 4. 全局变量与角色

本版本把 C# 类型中声明的字段视为全局信号：包括 `private/public/internal/protected`、静态字段和实例字段；不包含方法局部变量和参数。

`--variables-output` 生成制表符分隔的 UTF-8 文件：

```text
Signal	Role	ReadCount	WriteCount	Declaration
GlobalClass.Signal_B	Producer	2	0	Shared/GlobalClass.cs:8
Test.Signal_C	Producer+Consumer	1	2	Runtime/Fork A/Test.cs:12
```

角色按信号图方向定义：

- `Producer`：字段被读取并作为下游关系的输入。
- `Consumer`：字段被写入并作为关系的输出。
- `Producer+Consumer`：字段既被上游写入，又被下游读取，即中间商。
- `Unused`：在当前源代码根目录内只有声明，没有显式读写。

`ReadCount/WriteCount` 是静态源码引用计数，不是运行时次数。字段声明初始化计为一次写入。

`Declaration` 保留相对扫描根目录的真实路径，并统一使用 `/`，用于差异审计；其中的空格不会被抹掉。只有标准方程域名会把路径分隔符、空格和点转换为下划线。

## 5. 默认扫描范围

递归扫描 `*.cs`，默认跳过：

```text
.git  .vs  bin  obj  node_modules  packages  artifacts  TestResults
```

可用重复的 `--exclude` 追加目录名：

```powershell
fastsignaltrace-csharp.exe D:\Work\MyProject --exclude Generated --exclude third_party
```

UTF-8、带 BOM 的 UTF-8、UTF-16 LE/BE 会自动识别；无 BOM 且不是有效 UTF-8 时按 Windows 简体中文代码页 936 读取。

## 6. 退出码

| 退出码 | 含义 |
|---:|---|
| 0 | 扫描成功，包括“扫描成功但没有形成标准方程” |
| 2 | 参数错误或源目录不存在 |
| 3 | 没有找到可分析的 C# 文件 |
| 4 | 分析过程发生未处理错误 |

## 7. 静态分析边界

- 当前版本提供 C# 语义分析，不把 GDScript、C/C++、Rust、TypeScript 当成 C# 猜测处理。
- 可以在目标工程缺少部分外部依赖、不能完整编译时继续分析工程内能够绑定的字段。
- 反射、运行时生成代码、外部二进制内部状态、集合元素别名和完整跨方法返回值传播无法仅从当前语法可靠还原。
- 方程是保守的静态依赖摘要，不代表某次运行一定走到对应分支。

## 8. 发布信息

- 目标系统：Windows x64。
- 发布方式：.NET 8 自包含、单文件；运行时和 Roslyn 分析程序集全部整合进 `fastsignaltrace-csharp.exe`，目标设备不需要另带 DLL 或预装 .NET。
- release 包原则上只包含本 EXE 和本手册。
