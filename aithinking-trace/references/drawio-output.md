# 每次调用必须交付的调查流程图

每次调用 AIThinking-Trace 都必须交付与本次调查对应的可编辑 `.drawio` 文件，包括只推进部分步骤、继续已有调查或仍有未决问题的情况。流程图用于评估调查方向与收敛依据是否合理，属于必需结果，不是可选的展示附件。

## 归档参照与本次输出

已确认案例归档在 [../assets/golden-example.drawio](../assets/golden-example.drawio)，预览为 [../assets/golden-example.png](../assets/golden-example.png)。首次组织图面时查看归档图，借鉴布局、分支、证据汇合与收口方式；归档只提供结构参照，不自动提供当前问题的事实或结论。

使用用户指定的输出目录；未指定时使用当前工作区的 `1_AgentOutput/`，目录不存在则创建。以本次调查主题命名，例如 `<主题>_AIThinking-Trace.drawio`。继续同一调查时更新对应图；独立调查另建文件，不覆盖无关成果。当前调查的结果文件不写回技能归档资产。

## 在调查过程中建立图

起步时放入目标、噪声检查与四领域框架，后续将实际得到的观察、假设、测试、判断及跨领域关系逐步补入。不要只在最后画一条缺少分支依据的结论线。

图面保留以下结构，并按实际进展表达：

- 左侧紫色目标与右侧紫色收口节点，清楚显示本轮解决什么、最终决定什么。
- 四领域及各自状态，生产端与消费端 Pending 的原因分别标注。
- 问题动作指向的信号消费范围、最终消费者与由近到远的回溯方向。
- 假设、配置测试、结果与判断，保留无变化或暂缓支路的理由，以及多结果汇合关系。
- 核心效果指向两端解禁的证据连接、双焦点及主副锚点、日志缺口与准星。
- 从准星到修正方向、适用条件及最终动作的依据。

尚未到达的部分可以保持未开展或 Pending；未知内容不补造。未闭环时，右侧节点写明“未闭环”、当前缺口与下一步，不因必须交图就编造一个完成结论。

区分事实、假设、计划和已执行结果。用简短节点文字、状态标记及必要的连线说明表达关系，颜色只作辅助。最终收口可以包含条件分支，但应汇成一个明确处置规则。

## 可编辑性与可读性

节点、文本与连接线使用 Draw.io 原生可编辑元素，不能只把整张截图嵌入文件。可用可用的绘图工具或直接生成合法的 Draw.io XML；没有桌面应用不免除 `.drawio` 交付要求。

节点 ID 唯一，连线引用有效，文字不截断，箭头方向明确。图面过大时优先整理分区和走线，保留从目标到收口可追踪的主视图。可附 PNG 或 SVG 预览，但它们不能替代 `.drawio`。

## 交付前用图审视调查方向

沿本次调查主线和关键支路检查：

1. 每次展开是否仍服务于原目标，进入主线的观察是否有依据。
2. 动作焦点到消费范围的映射、由近到远的顺序是否表达清楚。
3. 假设是否经过相应测试，结果与判断是否连接，是否混入未经执行的结论。
4. 新证据是否指向它实际解禁的领域，多个结果的汇合是否有共同依据。
5. 准星是否由日志缺口追踪而来，修正方向与最终动作是否能由前面的关系解释。

只检查本次已推进部分；未开展部分明确标注。发现跳步或无依据的连接，补查必要信息或保留具体缺口，不为了让图看起来完整而补造节点或因果。

确认文件存在且图结构可解析、节点与连线可编辑。具备 Draw.io 或兼容渲染工具时，打开或导出预览检查排版；只完成结构检查时如实说明，不声称已目视验证。

最终回复必须包含实际 `.drawio` 文件的可访问链接，以及本轮是否闭环或仍缺什么的简短说明。没有交出文件时，不能把本技能的交付标为完成。
