# EqualAnalyzer Console 使用手册

EqualAnalyzer Console 接收 FastSignalTrace 的标准方程，并把它们建成可追踪的生产者/消费者图。它是独立 Console 工程，不修改旧版 WinForms EqualAnalyzer。

## 示例一：输入方程文件并打印 Trace PATH

直接把方程组文件作为第一个参数：

```powershell
equalanalyzer-console.exe equations.txt
```

程序默认在解析报告末尾打印 `[Paths]`，不需要额外开关。环路会先自动压缩成 `Loop(...)` 节点：

```text
[Paths]
======>[Root]===Signal.A===>[File_cs_100]===Signal.B===>[Loop(File_cs_120|File_cs_180)]===Signal.C===>[End]
======>[Loop(SelfLoop_cs_20)]
```

最后一个环节点没有下文，就表示该链路没有普通出口；第一个环节点没有 Root 前文，就表示没有普通入口。不额外打印黑洞或白洞占位文字。

## 标准方程

每行一条：

```text
Test_cs_1145:GlobalClass.Signal_B+Test.Signal_A=Test.Signal_C
```

冒号左侧是方程组名，等号左侧是输入信号，右侧是输出信号。输入或输出用 `+` 分隔；没有输出时使用 `NONE`。空行、`#` 和 `//` 开头的行会被忽略。可选的行尾 JSON 元数据必须用空格与方程分隔。

## 文件模式

```powershell
equalanalyzer-console.exe equations.txt --strict
equalanalyzer-console.exe equations.txt --json graph.json -o report.txt
equalanalyzer-console.exe equations.txt --trace-signal Middle.C
equalanalyzer-console.exe equations.txt --trace-equation Test_cs_1145
```

`--strict` 在任何非法行存在时返回退出码 3；默认模式会保留合法行并把错误写进报告。退出码 2 表示参数或路径错误，4 表示未处理异常，5 表示追踪目标不存在。

## 交互式“方程解析”

```powershell
equalanalyzer-console.exe --interactive
```

逐行录入方程后，输入空行或 `:parse`，即执行旧工具“方程解析”按钮对应的提交动作：解析全部行、建立生产者/消费者索引、生成依赖边、检测循环并输出报告。输入 `:io` 则提交并直接执行“IO分析”。

## IO 分析与标签反查

只按方程分组：

```powershell
equalanalyzer-console.exe equations.txt --io-analysis
```

再与 FastSignalTrace 变量 TSV 对照：

```powershell
equalanalyzer-console.exe equations.txt --io-analysis --variables variables.tsv -o io-report.txt
```

FastSignalTrace 信号角色契约为：等号左侧输入信号提供值，要求 `Producer`；等号右侧输出信号接收赋值，要求 `Consumer`；两侧都有则要求 `Producer+Consumer`。

IO 报告保留旧按钮的三种分组：`Only inputs`、`Only outputs`、`Remaining IO`，并列出信号位于哪些输入/输出方程。TSV 对照结果分为：

- `Exact`：方程角色与 TSV 标签完全相同。
- `CompatibleSuperset`：TSV 具有方程要求的全部能力，且还记录了方程范围外的读写。
- `Mismatch`：TSV 标签缺少方程明确要求的 Producer 或 Consumer 能力。
- `MissingDeclaration`：方程信号没有对应 TSV 声明。

同名 TSV 声明超过一行时还会计入 `Ambiguous declaration labels`，提醒调用方检查跨文件或跨项目信号身份碰撞。

## 循环与死锁线索

报告始终包含 `Cycles (potential deadlock/oscillation clues)` 区段。循环分为：

- `SelfLoop`：同一方程通过信号读写回到自己，例如 `Latch:Latch.Q=Latch.Q`。
- `StronglyConnectedComponent`：两个或更多方程互相可达。

每个循环同时列出内部依赖边及其信号。循环不会自动判定为死锁；它是后续时序、锁和线程工具进行复核的候选线索。JSON 输出中 `Cycles` 保留相同的类型、方程 ID 和内部边。

## 信号链路 Paths

每次解析都会打印 `[Paths]`，格式与旧工具一致：

```text
======>[Root]===Signal.A===>[File_cs_100]===Signal.B===>[File_cs_120]===Signal.C===>[End]
```

路径从没有上游生产方程的输入信号开始，以没有下游消费方程的输出信号结束。没有普通入口时省略 Root 边，没有普通出口时直接停在最后一个节点。

路径展开前先运行强连通分量分析，把闭环整体压缩成单个节点：

```text
======>[Root]===Signal.A===>[Loop(Domain_1|Domain_2|Domain_3)]===Signal.Z===>[End]
```

因此闭环不会造成无限递归，同时循环内的原始方程和信号仍完整保留在 `Cycles` 报告和 JSON `InternalEdges` 中。JSON 的 `Paths` 还提供结构化 `Nodes`、`Signals`、`ContainsCollapsedLoop`、`HasRootBoundary` 和 `HasEndBoundary`。

## 发布

在 `1_UserInputs/EqualAnalyzer` 执行：

```powershell
.\build-equalanalyzer-console-release.ps1
```

发布目录 `release-console` 只保留 `equalanalyzer-console.exe` 和本手册。
