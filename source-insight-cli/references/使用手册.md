# SourceInsightCli 2.1.0

独立 C/C++ 调用分析器，无需安装商业 Source Insight。Windows x64 发布包是 self-contained 单文件 EXE。源码构建需要 .NET 8 或更高 SDK，测试脚本另需 Python 3。

新增自包含 DLL 包：`releases/cpp/SourceInsightCli-2.1.0-win-x64-self-contained.zip`。完整解压后包含 SourceInsightCli.dll、EXE 启动器、runtimeconfig/deps 和本地 .NET 运行时，无需目标机安装 .NET。共享分析代码编入主 DLL，不依赖 CppAnalysis.Core.dll。不要仅复制 DLL 后宣称“无运行时依赖”；自包含是完整发布目录的属性。已有兼容 .NET 环境也可使用 `dotnet SourceInsightCli.dll <root>`。供 .NET 程序引用的公开入口为 `SourceInsightCli.Tool.Run(string[] arguments)`，返回 CLI 退出码。

直接运行 `SourceInsightCli.exe <source-root>`（或 `trace <source-root>`）会分析并在 stdout/echo 显示完整调用链，无需先 index。`--output` 同时保存文件，仍完整回显；index 子命令仍输出结构化统计。以下查询命令保持可用。

```powershell
SourceInsightCli.exe index D:\Code --output D:\Result\index
SourceInsightCli.exe symbols --index D:\Result\index --name notify_event --format json
SourceInsightCli.exe callees --index D:\Result\index --symbol entry
SourceInsightCli.exe callers --index D:\Result\index --symbol leaf
SourceInsightCli.exe path --index D:\Result\index --from entry --to leaf
SourceInsightCli.exe graph --index D:\Result\index --root entry --format mermaid --output D:\Result\calls.mmd
SourceInsightCli.exe bindings --index D:\Result\index --symbol ops.run --format json
SourceInsightCli.exe chains --index D:\Result\index --output D:\Result\all-calling-chains.txt
```

箭头始终为调用者 → 被调用者，Mermaid/DOT 使用 LR。它表示调用深度，不表示语句总时序。重名符号必须使用 symbols 给出的 ID。回调初始化与取地址是 binding，不是调用。回调参数记录进入调用点的 contextTargets；默认完整展开所有分支与候选，输出 Main -> Test1 -> Test2 形式。chains 从所有入口展开整个索引，独立函数和无自然入口的递归组件也保留；callees 从指定函数展开。path 展示两点间全部简单路径，但仍属于保守路径。

索引 manifest.json 指向一个不可变 generation 目录，内部有 index.json、symbols/calls/bindings/slots/diagnostics.jsonl。新索引写完才切换 manifest；旧 generation 保留供追溯。查询会检查已索引文件的内容 hash，变化时要求重建。输入树新增文件应重新 index。

实现范围：tolerant C/C++ 词法/结构解析、直接调用、函数指针 typedef、指定/位置初始化、字段/数组、对象别名、参数/返回传播、命名空间、同名 static 隔离、已知类型的方法候选。flow-insensitive 指针并集；宏分支为 conditional union，所有结果保留源码位置。无目标调用保留 unresolved，缺函数体的直接调用标 external-or-declaration-only，不靠同名字段或签名猜目标。

边界：不展开 include/宏、不解释 SCons、不提供配置/Clang 前端、完整 C++ 重载/继承/模板/隐式构造析构、路径条件证明或全程序精确性。相同参数个数的重载保留多候选；虚方法候选不证明实际动态类型。不支持的 --config、--define、--compile-commands 或 --parser clang 会明确拒绝。分支和指针覆盖可能扩大候选；不能据此证明运行时可达或死锁。

默认 depth/max-paths/max-nodes 均为 all，不省略深层调用、分支或函数指针候选。递归无法无限打印，完整保留到回边并显示 A -> B -> Loop(A)，不会静默丢弃。未解析调用显示 unknown 终点。只有用户显式传入数值预算时才限制，任何截断返回退出码 5 并标 complete=false。解析器仍有限定的不动点迭代与单槽别名展开预算，超限 manifest.truncated=true；查询完整性与目标解析精度不同。strict 额外将解析诊断/不确定性视为退出码 5。其他退出码：0 成功输出、2 参数或歧义、3 无输入/未找到、4 运行或 stale-index 错误。

指定 Harness 可执行：

```powershell
./tests/run-fixture.ps1 -Harness '<workspace>/3_HarnessProject/ADSP/lsm6dsv'
```

此脚本人工定义 API 表、回调链和负例断言，并检验两个工具共享调用索引、方程/TSV 闭包与重跑确定性。结果在 tests/actual/lsm6dsv/verification.json，PATH 与 LR 图在同目录；Harness 源码不改写。
