# 复杂信号业务分析约定

本参考文件定义 FastSignalTrace 扫描完成后的二次分析输出。顶层技能负责调用 EqualAnalyzer；本文件只规定解释、审计和驾驶舱落盘格式。

## 三层信号地图

| 层 | 典型拥有者 | 命名前缀 | 作用 |
| --- | --- | --- | --- |
| 终端层 | UI、IO、Executor、持久化适配器 | `ORIGIN_` | 产生原始意图或消费最终状态 |
| 信号汇集层 | ViewModel、Model/View bus、快照/反馈总线 | `MODELVIEW_` | 汇集、转运、分发，阻止终端短接 |
| 信号编织层 | SignalWeaver、状态机、决策、编排器 | `SIGNAL_` | 编织业务状态、批准/拒绝、执行意图和反馈 |

推荐的完整路径：

```text
ORIGIN_<scope>_<feature>_<name>
  → MODELVIEW_<scope>_<feature>_<name>
  → SIGNAL_<scope>_<feature>_<name>
  → MODELVIEW_<scope>_<feature>_<name>
  → ORIGIN_<scope>_<feature>_<name>
```

“终端”描述所有权，不等于 Producer。Producer/Consumer 方向必须由方程左/右侧和 `variables.tsv` 共同确认。

## PATH 审计规则

使用 EqualAnalyzer 的 `equation-graph.json`：

1. 对每一条 `Paths[*]` 读取 `Nodes` 和 `Signals`，保留 `Loop(...)` 的折叠表示。
2. 将节点或信号按命名前缀映射为 Endpoint、ModelView、SignalWeaver、Unknown。
3. 标记以下问题：
   - `ORIGIN → ORIGIN`：终端短接；
   - `ORIGIN → SIGNAL`：绕过汇集层；
   - `SIGNAL → ORIGIN`：反馈绕过汇集层；
   - 缺少任何预期层；
   - Unknown 节点或名称无法归类；
   - 跨层回环。
4. Source/Sink 是全图集合，不用单条路径的 Root/End 代替：
   - Source：只出现在输入、从未出现在输出的信号；
   - Sink：只出现在输出、从未出现在输入的信号；
   - 忽略 `NONE`。

## 命名审计与重命名表

重命名表建议使用 UTF-8 TSV，首行字段如下：

```text
old_name	new_name	layer	business_scope	feature	reason	status
```

`status` 初始为 `proposed`，用户确认后改为 `approved`，执行后改为 `applied`。表中每个 `old_name` 必须唯一，`new_name` 冲突必须先人工解决。

执行前必须：

- 输出表格预览和受影响文件计数；
- 按 `old_name.Length` 降序排序；
- 对旧字符串做正则转义，优先最长匹配；
- 默认只预览，用户明确同意后才使用 `-Apply`；
- 重命名后重新运行 FastSignalTrace 和 EqualAnalyzer，禁止用旧图作为结论。

## `Extra_SignalMap.md` 最小章节

可使用 `scripts/ensure-signal-cockpit.ps1 -SourceRoot <root>` 查找最近的 `00_STATUS`；没有时在源码根创建。该脚本只补缺失的目录/文件，不覆盖已有驾驶舱内容。

驾驶舱文件至少包含：

1. `Scan metadata`：SourceRoot、时间、语言、方程/变量/路径版本；
2. `Layer contract`：三层定义和允许的路径骨架；
3. `Source signals`：可靠性入口；
4. `Sink signals`：影响域入口；
5. `Focused path groups`：关注信号、每条路径原文、左右链路；
6. `Layer audit`：缺失层、bypass、Unknown、循环；
7. `Naming audit` 与重命名表链接；
8. `Static-analysis limits`；
9. `Next actions`。

## 消费行为与双缓冲审计

使用 `scripts/audit-signal-consumption.ps1 -EquationFile <equations.txt> -VariablesFile <variables.tsv> -SignalOnly` 扫描源文件。提供方程文件后，审计以 PATH 图中的信号集合为主要匹配边界，再用变量表补充声明信息；报告中的每个信号相关布尔表达式至少包含绝对文件路径、行号、上下文、操作符、识别到的信号和建议。需要全量语言布尔表达式清单时去掉 `-SignalOnly`，并读取 JSON 结果。

- `condition/consumer`、`return/consumer`、`call/consumer` 中出现 `&&`、`||`、`!`、`and`、`or`、`not`，标记为消费时计算候选违规；
- `precompute/assignment` 只表示可能已经提前计算，仍需核对左值是否是有业务含义且符合层级前缀的信号；
- 在 Tick/Update 类函数中同一状态信号同时出现在读集合和写集合，标记为单缓冲风险；必须存在 current/next、snapshot 或等价的统一交换点。

启发式扫描不能证明没有数据竞争。找不到风险时也要记录扫描扩展名、排除目录和“未检测到（启发式）”，并把需要人工复核的动态/宏/委托路径列入 `Static-analysis limits`。
